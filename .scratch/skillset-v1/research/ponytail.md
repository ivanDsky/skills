## What it is

Ponytail is a distribution of **one behavior prompt** — "lazy senior dev mode": the smallest change that fully solves the task, never cutting validation, security, accessibility, or data-loss handling, and ending every reply with what was skipped and what risk remains (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/README.md, https://raw.githubusercontent.com/DietrichGebert/ponytail/main/AGENTS.md). The README says it plainly: "Ponytail is one prompt: `skills/ponytail/SKILL.md`. The compact version ... is `AGENTS.md`. Everything else in this repo loads that prompt into different agents."

- **Scale/activity:** 180,149 stars, 9,878 forks, MIT, created 2026-06-12, last push 2026-10-29 (https://api.github.com/repos/DietrichGebert/ponytail). Version 5.3.3 (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/.claude-plugin/plugin.json).
- **Ship shape:** the same six skills (ponytail, -review, -audit, -debt, -gain, -help) wrapped for ~20 agent hosts — Claude Code, Codex, Copilot CLI, Cursor, OpenCode, Gemini CLI, Qwen, Pi, Kimi, Hermes, Goose, Devin, Grok, OpenClaw, Antigravity, and a rules-file fallback for the rest (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/INSTALL.md, https://raw.githubusercontent.com/DietrichGebert/ponytail/main/docs/agent-portability.md).
- **The six skills** (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/skills/ponytail/SKILL.md and siblings):
  - `ponytail` — the always-on mode with intensity levels lite/full/ultra/off; a 6-rung ladder (need it? → already in codebase → stdlib/platform → existing dep → one line → minimum that works), a "never cut" guardrail list, and a rule that non-trivial logic leaves one small test behind.
  - `ponytail-review` — diff review that reads the code the change touches, not just the diff; checks bugs, security, load, missing tests, speed, and what to cut; each finding states what the code does, what goes wrong, the fix, and the cost of skipping.
  - `ponytail-audit` — the same checks repo-wide, ranked "fix this first", read-only, one-shot.
  - `ponytail-debt` — greps `shortcut: <ceiling>, <upgrade path>` comments into a debt ledger; flags markers with no upgrade trigger as rot risks; read-only unless asked to persist.
  - `ponytail-gain` — prints a static benchmark scoreboard (marketing card).
  - `ponytail-help` — prints a command reference card.

## How it works

**Core mechanic (Claude Code plugin):** lifecycle hooks run small Node scripts. `SessionStart` (matcher `startup|resume|clear|compact`) reads the persisted mode and injects the SKILL.md body as session context; `UserPromptSubmit` watches for `/ponytail ...` commands, writes a mode flag file, and stays silent on ordinary prompts; `SubagentStart` injects the same ruleset into every spawned subagent, scoppable via a `PONYTAIL_SUBAGENT_MATCHER` regex (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/hooks/claude-codex-hooks.json, https://raw.githubusercontent.com/DietrichGebert/ponytail/main/hooks/ponytail-mode-tracker.js, https://raw.githubusercontent.com/DietrichGebert/ponytail/main/INSTALL.md). The instructions builder even filters the SKILL.md body per level, so `lite` sessions don't carry `ultra` rows (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/hooks/ponytail-instructions.js).

**Other hosts:** OpenCode/Pi/Kimi/Qoder-style hosts inject the ruleset *every turn* via their plugin systems; Gemini ships it as always-on extension context; rules-file-only hosts (Cursor rule, Cline, Windsurf, Copilot Chat) just load `AGENTS.md` and get no commands or level persistence (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/INSTALL.md). The skills-CLI path (`npx skills add`) copies only the six skills — no hooks, so no auto-activation and no mode persistence; activation then comes from the skill descriptions, which say "Use on any coding task ..." (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/INSTALL.md).

**Benchmarks — do they measure anything real?** Yes, and they are unusually honest. The headline agentic benchmark runs 585 headless Claude Code sessions (39 tasks × 5 runs × 3 arms) on a real FastAPI+React repo and seeded stubs; the no-skill arm is the same agent without the skill (a fair baseline, added after issue #126 called out that the original single-shot benchmark over-counted chatty prose); stats are per-task medians, geometric means, 95% bootstrap intervals, sign tests; 18 surgical tasks have deterministic hidden checks that execute the produced code against adversarial input; agent-written tests are mutation-tested by injecting bugs; reply quality is a blind judge with a self-test (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/benchmarks/README.md, https://raw.githubusercontent.com/DietrichGebert/ponytail/main/benchmarks/agentic/README.md, https://raw.githubusercontent.com/DietrichGebert/ponytail/main/benchmarks/results/2026-10-07-agentic.md). Headline: Ponytail 5 vs no skill = -53% LOC, -45% output tokens, -26% cost, -41% time, hidden checks 96.7% vs 95.6% (no safety regression), a test where the logic needs one 98% vs 68%. Honest limits are published in-file: cost interval includes -5%, the privacy task fails 3/5 runs in *all* arms, and vs no skill the reply-judge found no significant difference (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/benchmarks/results/2026-10-07-agentic.md). One independent external benchmark is linked (≈44% less code, no correctness/security regression, trim of some bad-input handling on 5/24 tasks) (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/benchmarks/README.md).

## Install & footprint

**Option A — Claude Code plugin (full behavior):** two separate prompts: `/plugin marketplace add DietrichGebert/ponytail` then `/plugin install ponytail@ponytail` (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/INSTALL.md). Requires `node` on PATH (hooks are `node -e` commands; without it the skills still work but each hook errors harmlessly) (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/INSTALL.md). Lands: the six skills, six `commands/*.toml` slash commands, three hooks, the Claude Code "band" UI + local board (needs Claude Code ≥ 2.1.290), a statusline script copy, mode flag `~/.claude/.ponytail-active`, config `~/.config/ponytail/config.json`, and a per-project CSV ledger `~/.config/ponytail/band/<project>.csv` (telemetry is local by default; an optional webhook can export rows, token kept in the system keychain) (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/.claude-plugin/plugin.json, https://raw.githubusercontent.com/DietrichGebert/ponytail/main/README.md). Uninstall leaves state behind; `node scripts/uninstall.js` cleans it (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/INSTALL.md).

**Option B — our distribution channel, skills CLI:** `npx skills add DietrichGebert/ponytail` (pick agent with `--agent`, all six with `--skill '*'`, `--global` for user-level) — copies the six skills only; uninstall: `npx skills remove ponytail ponytail-audit ponytail-debt ponytail-gain ponytail-help ponytail-review` (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/INSTALL.md).

**Option C — vendoring:** MIT permits copying; the behavior is one 3.0 KB prompt body (`AGENTS.md` or the SKILL.md body).

**Per-session context cost (measured from the files, ≈4 chars/token):**
- Full plugin, Claude Code: `ponytail` body ≈ 3,029 chars ≈ **~760 tokens at SessionStart**, repeated per subagent via `SubagentStart` (matcher-scopable); ~0 on ordinary turns (mode-tracker is silent unless you type a `/ponytail` command) (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/hooks/ponytail-instructions.js, https://raw.githubusercontent.com/DietrichGebert/ponytail/main/hooks/claude-codex-hooks.json). Skills' bodies load on invocation (audit ≈ 1,254 tok, review ≈ 1,179 tok, debt ≈ 379 tok) (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/skills/ponytail-audit/SKILL.md etc.).
- Skills-CLI-only: no injection; just the six name+description rows ≈ 1,584 chars ≈ **~400 tokens** always present (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/skills/).
- Rules-file hosts: `AGENTS.md` = 2,721 chars ≈ **~680 tokens every turn/session** (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/AGENTS.md).
- OpenCode/Pi/Kimi/Qoder plugin: ~760 tokens **every turn** (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/INSTALL.md).

## Adoption verdict

Context: our skillset (`ivanDsky/skills`, `npx skills` distribution) plans v1 flow chains for greenfield and brownfield work. Ponytail is a *governor* (how much to build) plus three genuinely useful read-only lenses; it is not a flow, so it mostly complements. The one real friction: `full` mode is on by default for **every** coding task, including our chains' deliberate-structure moments (TDD, scaffolding, prototypes). All quotes/mechanics above are cited; verdicts below.

- **`ponytail` (the mode) — integrate-adapt.** The value is one page of text (the ladder + "never cut" list + skip/risk reply rule); vendor that into our own skill with attribution, with activation we control (on-invocation or `lite` default), instead of an always-on persona with Node hooks and flag files. Install-as-is is the fallback if the user wants the benchmark-backed original and its 20-host updates.
- **`ponytail-review` — install-as-is** (via `npx skills add`, pick this skill). Self-contained, one-shot, zero persistent context beyond its description; the "read connected code, not just the diff" + ranked findings format is the strongest single addition for our brownfield chain. If the user's existing `code-review` skill stays, downgrade to integrate-adapt so we don't ship two review commands with different semantics.
- **`ponytail-audit` — install-as-is.** Whole-repo ranked audit, read-only, distinct capability, no collision; ideal brownfield-onboarding companion ("the senior dev who just inherited it").
- **`ponytail-debt` — install-as-is.** Tiny (~380-token body), read-only ledger of `shortcut:` comments; pairs directly with the minimal-change mode's marker convention. If we vendor the core prompt, keep its `shortcut:` convention so the ledger stays meaningful.
- **`ponytail-gain` — skip.** A static marketing scoreboard; prints benchmark numbers, explicitly refuses per-repo figures; no workflow value.
- **`ponytail-help` — skip.** Reference card for ponytail's own commands; meaningless if we vendor parts, redundant if we install the plugin (it comes along anyway).

## Surprises & open questions

1. **"180k stars" is real** — 180,149 (https://api.github.com/repos/DietrichGebert/ponytail), on a repo created 2026-06-12; extraordinary velocity, but star count is not a quality signal we weighted.
2. **The benchmark rigor is the real product differentiator.** Paired arms, hidden adversarial checks, mutation-tested tests, blind judges with self-tests, bootstrap CIs, and published negative results (reply-judge found no significant win vs no skill; privacy task fails everywhere) (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/benchmarks/results/2026-10-07-agentic.md). Few prompt repos do any of this.
3. **Supply-chain posture is thoughtfully paranoid:** README warns to install only from his GitHub/npm and that builds "never ship `.exe` or `.dll`"; hooks are short readable JS; the optional webhook keeps its token in the system keychain (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/README.md, https://raw.githubusercontent.com/DietrichGebert/ponytail/main/.claude-plugin/plugin.json). Still: the plugin runs Node hooks on every session start and every prompt — a supply-chain surface our own vendored-skills approach wouldn't have.
4. **Uninstall is incomplete by design of the hosts** — flag files, config, statusline copy, and `hooks.json` entries survive `/plugin remove`; a separate script (which deletes itself if you remove the plugin first) cleans up (https://raw.githubusercontent.com/DietrichGebert/ponytail/main/INSTALL.md).
5. **Open question — default level for our users:** if we vendor the core prompt, should our version default to `lite` ("build what was asked, name the smaller option") rather than `full`, so it never fights our flow chains unless summoned?
6. **Open question — `shortcut:` vs our debt tracking:** if our brownfield chain grows its own deferral marker, we should adopt ponytail's `shortcut: <ceiling>, <upgrade path>` format verbatim (it's well-designed: ceiling + trigger + rot-flagging) rather than inventing a second convention.
7. **Open question — review overlap:** does the user's installed `code-review` skill (standards+spec axes) stay? That decides install-as-is vs integrate-adapt for `ponytail-review`.
