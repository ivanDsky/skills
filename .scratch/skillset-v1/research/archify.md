# T016 — Adoption survey: tt-a1i/archify

Surveyed 2026-10-29 from primary sources at `https://github.com/tt-a1i/archify` (default branch `main`, skill version 3.2.0, released 2026-10-18 per [CHANGELOG.md](https://raw.githubusercontent.com/tt-a1i/archify/main/CHANGELOG.md)).

## What it is

Archify is a **single agent skill** (not a hosted service, not an npm library) that turns an idea, a plan, or a codebase into a **validated, standalone interactive HTML diagram** — or, in its newest mode, a one-page "explainer" answer document ([README.md](https://raw.githubusercontent.com/tt-a1i/archify/main/README.md), [archify/SKILL.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md)).

- **Skill + CLI, both.** The installed package is a skill folder (`archify/` with `SKILL.md`) that carries its own zero-dependency Node CLI (`archify/bin/archify.mjs`). The agent authors a typed JSON intermediate representation; the CLI renders and verifies it ([archify/SKILL.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md), [archify/package.json](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/package.json)).
- **Ten diagram types**: architecture, workflow, sequence, dataflow, lifecycle, ERD, class, tree, timeline, waterfall — each with a JSON schema and worked example in-package ([archify/schemas/](https://github.com/tt-a1i/archify/tree/main/archify/schemas), type router in [archify/SKILL.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md)).
- **Explainer (new in 3.2.0)**: a conclusion-first one-page HTML with panels, tables, charts, and embedded diagrams, authored as Markdown and delivered through the same validation pipeline ([CHANGELOG.md §3.2.0](https://raw.githubusercontent.com/tt-a1i/archify/main/CHANGELOG.md)).
- **Mermaid input accepted** as topology: `flowchart`→workflow/architecture, `sequenceDiagram`→sequence, `stateDiagram`→lifecycle, `erDiagram`→erd, `classDiagram`→class; meaning is re-authored into Archify JSON, not restyled ([archify/SKILL.md §Mermaid input](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md)).
- **Repo-backed diagrams**: for real codebases it pins `git rev-parse HEAD` + credential-free origin into the artifact, verifies cited evidence against committed bytes, and links nodes to source ([archify/references/repository-authoring.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/references/repository-authoring.md)).
- Popularity markers on the README: Trendshift badge, `130K+ installs on skills.sh` badge ([README.md](https://raw.githubusercontent.com/tt-a1i/archify/main/README.md)). I did not independently verify the 91k-star figure from the ticket.

## How it works

1. **Agent authors JSON IR** against a schema, guided by progressive-disclosure references (authoring defaults, per-type rules, delivery contract) loaded only when triggered ([archify/SKILL.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md)).
2. **One command validates and ships**: `node bin/archify.mjs finalize <type> <candidate.json> <output.html> --quality showcase --json`. `finalize` chains gates — schema validation (validators generated from the JSON schemas via ajv, a dev-only dependency), layout/route/label-clearance checks in the Node renderers, atomic delivery, strict provenance check — and only after all earlier gates pass does it **launch a private headless Chrome** for the `browser-check` gate ([archify/SKILL.md §Delivery](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md); [archify/references/delivery-contract.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/references/delivery-contract.md); dev deps in [archify/package.json](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/package.json)).
3. **Browser automation is dependency-free**: `visual-check.mjs` finds Chrome/Chromium on PATH (or standard install locations) and drives it over `--headless=new --remote-debugging-pipe` — no Puppeteer/Playwright, no downloaded browser ([archify/bin/visual-check.mjs](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/bin/visual-check.mjs), `chromeVisualBrowserArgs` / `findChrome`).
4. **Output is one self-contained HTML file**: embedded viewer JS/CSS with focus, upstream/downstream reach, route probe, lens, presentation stage, dark/light themes, i18n (en/zh/es/ko/ar bundled), PNG/SVG/WebM export and share cards; offline self-containment is a tested contract, fonts (JetBrains Mono) are bundled ([README §Explore and share](https://raw.githubusercontent.com/tt-a1i/archify/main/README.md); [archify/viewer/](https://github.com/tt-a1i/archify/tree/main/viewer); [test/offline-self-containment.test.mjs](https://github.com/tt-a1i/archify/blob/main/test/offline-self-containment.test.mjs)).
5. **Failures come as repair receipts**: stable rule codes + measured evidence instead of stack traces; repair rounds are bounded and receipts record what passed ([archify/references/delivery-contract.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/references/delivery-contract.md)).
6. **Update check (opt-out)**: `finalize`/`deliver` GET a fixed manifest at `https://tt-a1i.github.io/archify/skill-updates/archify/stable.json` (~24h backoff) to show an update reminder only; it never installs; disable with `ARCHIFY_UPDATE_CHECK_DISABLED=1` ([archify/skill-release.json](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/skill-release.json); [README §Quick start](https://raw.githubusercontent.com/tt-a1i/archify/main/README.md)).

## Install & footprint

Documented install (same `npx skills` distribution we already chose for our skillset):

```bash
npx skills add tt-a1i/archify -g                                  # README quick start
npx -y skills add tt-a1i/archify --skill archify --agent cursor --global --copy --yes   # explicit/non-interactive
npx skills use tt-a1i/archify@archify --agent codex               # try without installing
```
([README.md §Quick start](https://raw.githubusercontent.com/tt-a1i/archify/main/README.md)). The repo's own [AGENTS.md](https://raw.githubusercontent.com/tt-a1i/archify/main/AGENTS.md) confirms discovery should resolve to **exactly one skill named `archify`** (`npx -y skills add <source> --list --full-depth`).

- **What lands where**: per the README installation table, the skill folder goes to `~/.claude/skills/` or `.claude/skills/` (Claude Code), `~/.agents/skills/` or `.agents/skills/` (Codex CLI), `~/.config/opencode/skills/` etc. (opencode). Claude.ai takes the `archify.zip` upload; Project Knowledge gets a prompt-only fallback ([README.md §Installation options](https://raw.githubusercontent.com/tt-a1i/archify/main/README.md)).
- **Disk footprint**: `archify.zip` at HEAD is **5,400,645 bytes ≈ 5.4 MB** ([git tree blob entry](https://api.github.com/repos/tt-a1i/archify/git/blobs/a1a87608b2b21e17345acedcb83360d6a76eaa82)). It is a deterministic zip of only the tracked, cleaned `archify/` folder (no `.git`, no dev scripts, `package.json` cleaned) per [scripts/build-zip.sh](https://raw.githubusercontent.com/tt-a1i/archify/main/scripts/build-zip.sh) + [scripts/stage-clean-skill.mjs](https://github.com/tt-a1i/archify/blob/main/scripts/stage-clean-skill.mjs).
- **Runtime deps**: Node **≥ 18** (`engines` in [archify/package.json](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/package.json)) and, for the browser-check gate, a locally installed Chrome/Chromium. **No `npm install` inside the skill** — "No install is required inside the skill package" ([archify/SKILL.md §Setup and fallback](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md)). Rendering itself is pure Node; the browser only verifies.
- **Per-session context cost**: the always-loaded surface is the frontmatter description (~1.4 KB, roughly 350–400 tokens) in [archify/SKILL.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md). On invocation the full SKILL.md is ~18.7 KB (≈ 4.5–5k tokens); the eight `references/*.md` files (8–49 KB each, per [git tree](https://api.github.com/repos/tt-a1i/archify/git/trees/main?recursive=1)) load only on their stated triggers.
- **Output location**: per request, `.archify/<type>-<slug>-<YYYYMMDD-HHMMSS>/` in the working directory, holding `candidate.json` + `<slug>.html` + receipt sidecars ([archify/SKILL.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md)).
- **Sanity check after install**: `node <skill>/bin/archify.mjs doctor` and `node <skill>/bin/archify.mjs demo <outdir>` ([archify/SKILL.md §Setup and fallback](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md)).

## Adoption verdict

| Item | Verdict | Why |
|---|---|---|
| `archify` skill (the whole `archify/` package) | **install-as-is** | Self-contained (Node ≥18, no npm install), Apache-2.0, installs via the same `npx skills add` flow we standardized on (T004), and it fills a capability none of our current skills have: verified, source-linked interactive diagrams. |
| Brownfield orientation (repo-backed diagrams) | **install-as-is (core use)** | Pinned-commit evidence + source-linked nodes is exactly the "orient in an unfamiliar codebase" step of our brownfield chain ([repository-authoring.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/references/repository-authoring.md)). |
| Spec viz (workflow/sequence of our v1 flow chains) | **install-as-is (core use)** | Ten typed modes + `compare architecture base.json head.json` delta receipts map directly onto visualizing our chains and before/after skillset changes ([README.md](https://raw.githubusercontent.com/tt-a1i/archify/main/README.md)). |
| Map rendering (render MAP.md / repo tree as a diagram) | **integrate-adapt** | Tree/architecture modes can render our skillset map, but nothing auto-converts MAP.md → JSON IR; we'd add a thin recipe in our own repo, not fork archify. |
| Explainer mode incl. `[archify explainer: proactive]` rules-line opt-in | **integrate-adapt** | The one-page answer is useful, but the proactive/always-on rules lines that write into `~/.claude/CLAUDE.md` should stay off by default in our skillset; keep it on-request only ([archify/SKILL.md §Output](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/SKILL.md)). |
| Update-check phone-home | **integrate-adapt** | Ship our install doc with `ARCHIFY_UPDATE_CHECK_DISABLED=1` (or accept it consciously); it's a GET to GitHub Pages with disclosed payloads, but our skillset should be deterministic/offline by default ([README.md §Quick start](https://raw.githubusercontent.com/tt-a1i/archify/main/README.md)). |
| Repo dev skills `.agents/skills/{archify-review, archify-tuning, simplify-codebase, test-value}` | **skip** | These are archify's own repo-development QA skills (tuning benchmarks, PR review), not part of the published skill; adopting them would vendor someone else's internal process ([git tree](https://api.github.com/repos/tt-a1i/archify/git/trees/main?recursive=1)). |
| Vendored `pele` chart lib, brand-marks catalog, locales | **skip (leave as-is inside the package)** | Internal implementation details of the installed skill; nothing to adopt separately ([archify/explainer/vendor/pele/README.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/explainer/vendor/pele/README.md)). |

**Exact steps if adopted**

1. `npx skills add tt-a1i/archify -g` (pick per-agent flags as in the table above).
2. Verify: `node ~/.claude/skills/archify/bin/archify.mjs doctor && node .../archify.mjs demo /tmp/archify-demo`; open the demo HTML.
3. Decide the update-check posture; if offline-first, export `ARCHIFY_UPDATE_CHECK_DISABLED=1` in our shell profile.
4. Record in our skillset README: requires Node ≥18 + local Chrome for full verification gates; browser evidence can report `skipped` without Chrome ([delivery-contract.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/references/delivery-contract.md)).
5. Optional integration: one recipe skill of ours that maps MAP.md/tickets → archify `tree`/`workflow` JSON.

## Surprises & open questions

- **Much bigger repo than the product**: 1,334 tracked paths — journals, evidence screenshots, benchmarks, a whole Astro website, community integrations — but the distributed skill is only the cleaned `archify/` folder, so none of that lands on install ([git tree](https://api.github.com/repos/tt-a1i/archify/git/trees/main?recursive=1); [build-zip.sh](https://raw.githubusercontent.com/tt-a1i/archify/main/scripts/build-zip.sh)).
- **Phoning home is on by default**: the update reminder GETs `https://tt-a1i.github.io/archify/skill-updates/archify/stable.json` during delivery unless `ARCHIFY_UPDATE_CHECK_DISABLED=1`. Disclosed in detail (no version/agent/project payload; server sees IP+time), but it is still a default-on network call from a diagram tool ([README.md §Quick start](https://raw.githubusercontent.com/tt-a1i/archify/main/README.md)).
- **The browser is only a verifier**: rendering is pure Node; Chrome (found on PATH, driven over the CDP pipe) runs only for the final browser-evidence gate, and launches only after cheaper gates pass. No Puppeteer anywhere ([visual-check.mjs](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/bin/visual-check.mjs); [delivery-contract.md](https://raw.githubusercontent.com/tt-a1i/archify/main/archify/references/delivery-contract.md)).
- **5.4 MB on disk, ~5k tokens on invocation** — the heaviest skill we'd carry, justified by in-package schemas/examples/renderers. Context cost is well-managed by progressive disclosure.
- **License history is unusual**: an Apache-2.0 transition that preserved prior MIT grants (dual files, explicit NOTICE language). Fine for adoption; just keep NOTICE when we redistribute or mirror ([NOTICE](https://raw.githubusercontent.com/tt-a1i/archify/main/NOTICE)).
- **Open**: (1) Does plain `npx skills add tt-a1i/archify -g` prompt when a repo contains multiple SKILL.md dirs (the repo carries 4 dev skills under `.agents/skills/`)? AGENTS.md implies discovery resolves to one named `archify`, but I haven't run the CLI. (2) Version pinning story for `npx skills` installs (skills.sh tracks `tt-a1i/archify/archify`; update channel is the GitHub Pages manifest) — we should decide pin-vs-track. (3) Actual star count (ticket says 91k) not independently verified; README-verified signal is the 130K+ skills.sh installs badge.
